# Архитектура доставки контента (Serverless CMS)

Этот репозиторий описывает и реализует схему доставки информации для статического веб-сайта. Мы используем Google Таблицы в качестве интерфейса для редактирования контента и Yandex Cloud (S3) в качестве хранилища и хостинга, полностью исключая необходимость в классическом бэкенде и базах данных.

## Как циркулируют данные (Data Flow)

Процесс доставки информации от редактора до конечного пользователя можно разделить на 4 этапа:

### 1. Источник данных (Google Sheet)
Весь контент (товары, тексты, настройки) редактируется в Google Таблице. 
При любом изменении срабатывает триггер `onEdit`, который устанавливает флаг `changed = true` в свойствах скрипта.

### 2. Обработка и синхронизация (Google Apps Script)
Скрипт (`google_script.txt`) периодически проверяет флаг изменений (`syncIfChanged`). Если изменения есть:
* Он берет данные из таблицы и конвертирует их в CSV-формат.
* **Важно:** К файлу добавляется BOM (EF BB BF) для корректного отображения кириллицы в кодировке UTF-8.
* Скрипт формирует подпись запроса (AWS Signature V4) и отправляет **PUT-запрос** в Yandex Cloud Object Storage, перезаписывая файл `data.csv`. Для этого используется сервисный аккаунт (Uploader Service account) с правами только на запись.

### 3. Хранение (Yandex Cloud S3 Bucket)
В облачном бакете хранятся все статические файлы:
* `index.html`, `style.css`, `script.js`, `data.csv`
* `data.csv` (обновляется скриптом из Google Таблиц)
* Сервисный аккаунт имеет минимальные права (только загрузка файла), что обеспечивает безопасность ключей.

### 4. Доставка и отображение (Браузер + imgbb)
Когда пользователь заходит на сайт:
* Браузер загружает HTML, CSS и JS из S3-бакета.
* Скрипт `script.js` делает `fetch`-запрос к файлу `/data.csv` и парсит его с помощью библиотеки `PapaParse`.
* На основе полученных данных динамически отрисовывается каталог, подставляются контакты и инициализируется карта.
* **Медиафайлы:** Сами картинки товаров не хранятся в S3. В CSV передаются только URL-адреса, а браузер пользователя скачивает изображения напрямую с хостинга `imgbb`.

## Ключевые особенности реализации
* **Zero-Backend:** Сайт полностью статичен, вся логика управления контентом вынесена в Google Apps Script.
* **Безопасность:** Ключи доступа (`ACCESS_KEY`, `SECRET_KEY`, `TABLE_ID`) хранятся в `PropertiesService` скрипта и не попадают в код.
* **Отказоустойчивость:** Если скрипт синхронизации временно недоступен, сайт продолжает работать на последней версии `data.csv`.
